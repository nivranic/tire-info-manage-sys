## 最终行为

- 共享 `AIAnalysisReference` 新增 Safety Gate 精确引用；`AIPrepareRequest` 支持指定周报和告警的在线重核。设备离线 `OfflineReference` 和知识搜索引用不扩域。
- 告警入口只取当前周报结果的 provenance，按快照＋原生告警 ID 绑定；历史观察入口使用该次观察快照，保留历史范围。
- 复用 AI 对话框、外发确认、预算与请求标识。新准备的包不继承 AI 外发同意；失败回退另需单次确认。共享 Native 工作台继续采用既有桥接及进度轮询。
- 包预览、流式草稿、最终分析、保存及恢复报告均展示适用性未评估边界。含 Safety Gate 的展示范围只保留事实，隐藏推断与自由不确定性说明。
- “从周报原件核对这条告警”调用源专属历史证据端点，核对快照、周报 query、来源 URL、原件 SHA256、原生告警 ID 和通报编号。XML 仅按纯文本展示；DOCTYPE、损坏 XML、重复身份或错绑拒绝。切换会话／目标或关闭组件时取消读取，迟到响应不采纳。

原始失败未覆盖：

1. `ui-red.log`：helper 尚未实现时模块缺失；实现后 4 组新增测试通过。
2. SDK 测试最初误用不存在的 `OfflinePackReference` 类型，按当前导出改为 `OfflineReference`；负类型断言和 SDK 检查通过。未扩设备域。
3. 浏览器首次分析提交返回 `net::ERR_NO_BUFFER_SPACE`，API 无该提交记录、模型调用 0。界面先只读核对 404，再沿用原标识提交成功，仅调用一次合成模型。底层浏览器错误原因尚未确定，没有新增重试或降级逻辑，首次 3 项失败观察保留。
4. HTTP 工装将 `/v1/fallback-consents` 的成功创建状态预期为 200，实际正常返回 201；原回执 `http-acceptance-r1.json` 保留，按端点合同修正后 26 项通过。
5. 页面脚本在恢复上次调用后提前查找时间范围单选框，产生选择器错误；按现有“重新准备证据，开始新的分析”入口操作后，在线与单次回退流程通过。
6. 首次关闭前发现两个子进程，未执行停止；确认是本轮创建的 conhost 助手后才关闭。最终五个自有进程、Parser 子进程和 8010／3070 监听均为 0。
