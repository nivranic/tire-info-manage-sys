# 2026-10-26 URL迁移事件切片（迁移032）证据报告

分层验收口径：本切片为**源码+合成验收**。无真实 HTTP 抓取、无真实模型调用、无设备行为；
未触碰保留 SQLite 与默认 API；KIT C2 UUID 封存不变。

## 1. 范围与需求来源

剩余 P2 工程项中「剩余监控」域的推进切片：来源地址迁移事件（url_moved）。该事件在 R134
来源原文监控（029）落地时被显式延后（029 计划文档列为 out-of-scope）。语义规格见
`docs/plans/2026-10-26-source-page-url-moves.md`。

**事件语义（冻结不变量）**：同 source + canonical query 相邻两次成功观察（前次 ok/not_modified，
本次 ok）URL 不同即产生一条 url_moved 事件；内容哈希不参与；A→B→A 记两次事件；与
page_changed 互斥（URL 不同时原文比较链换基线，沿用 R134 口径）；Kind `url_moved` 与
`page_changed` 对称——独立监控、无 fields/conditions/variant、仅轮胎来源、模式不可互换。

## 4. 重要发现：HEAD 潜伏红（先于本切片存在）

**现象**：`_TRIGGER_CONTRACT`（`tests/historical_migration_support.py`）未收录迁移
029/030/031 引入的 after_create 触发器家族（source_page、ai_price、test_event_golden），
而全部 10 个里程碑调用方的夹具均以 `create_app + create_all(当前形态)` 构建 before 态，
这些家族必然在场——`assert set(actual) == set(expected)` 在 HEAD（1416ece）即失败。

**实证**（git worktree 独立检出一字未改）：HEAD 上
`test_device_ai_migration013`（3 败）、`test_ai_stream_migration`（1 败）、
`test_device_ai_migration012`（1 败）共 5 败，失败点全部是契约集合断言。本切片初测的
6 个失败中 5 个与 HEAD 完全同形，第 6 个家族（032 触发器）为本切片新增差集。

**为何未被发现**：受管 runner 默认清单**包含**这些里程碑文件（清单本身无缺口），但
R136 之后的全量复核批（`fullreview-20261026`、`fvr-*` 系列）均使用显式目标列表，
恰好未含迁移里程碑文件；本地直接 pytest 迭代也只跑了当轮改动相关文件。

**修复**：契约补 9 表——ai_price_versions、test_event_golden_{cases,case_revisions,
case_reviews,set_revisions}、source_page_changes、source_page_url_moves（标准
no_update/no_delete/no_replace 模板）+ source_page_notifications、
source_page_url_move_notifications（新五元组 `notification` 风格：`read_only_update`
NEW/OLD 固定六列比较 + no_delete + no_replace，与 029/032 实际 DDL 逐字一致，
canonical 归一后校验）。契约头注与 `NOTIFICATION_FIXED_COLUMNS` 同步声明为 test-owned。
