# PostgreSQL 车型 024 显式迁移计划

**Goal** — 让已有文本车型证据的 PG 库通过显式维护入口升级为 024，保留旧行、引用、索引和约束，并验证失败回滚及备份恢复。

**Architecture** — 复用既有证据校验、PG 显式连接配置和隐藏密码输入。PG 使用事务内 ALTER TABLE，沿用 schema 与 ingestion advisory 锁。维护事务锁住既有业务表，先用导出快照生成全新 pg_dump 备份，再升级目标结构与版本。正常启动继续通过 preflight 判断迁移状态。

**Tech Stack** — PostgreSQL、SQLAlchemy、pg_dump／pg_restore、现有受管回归和隔离 PG 验收。

## 实施顺序

1. 用正式历史 015 源码重建独立 PG，验证四张表的最小 DDL，再与当前空参考合同逐项比较。
2. 扩展既有证据校验的 PG 读取，新增显式 PG 迁移函数。锁内核对旧结构、原件哈希和引用，记录旧列／行及结构，完成 016–023 增量步骤后改四表，最终记录 024。
3. 运维入口接受明确 PG profile、现有 PG 工具目录、全新备份文件和停写确认。密码隐藏输入，pg_dump 经管道继承进程凭据，输出固定失败码。备份完成后再执行 DDL。
4. 隔离验收覆盖历史数据、原件、版本、约束、重复执行、正常启动、四阶段失败回滚、坏证据／部分结构／并发锁拒绝和独立备份恢复。
5. 运行受管启动、SQLite 旧迁移、CLI、Worker 回归及真实 PG 验收。核对源文件绑定、集群和临时秘密关闭，更新交接与部署说明，提交推送。

## 验收边界

既有旧列逐行保持，新增 body_encoding 为 utf-8，raw_capture_id 保持 NULL。PG 外键全程有效。对象与 Parser 资产由现有部署备份流程保全，DB 入口返回其覆盖范围。生产部署与完整 V1 仍按原发布 Gate 验收。
