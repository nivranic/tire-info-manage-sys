# Dunlop欧洲官方规格来源接入

原规格将Dunlop列为P0待专项验证来源。本阶段选择欧洲SPORT MAXX RT2固定产品页，沿既有在线优先、公共DNS校验、robots、限频、条件读取、原件捕获和隔离Parser流程接入。

## 当前来源证据

2026-11-14欧洲robots与目标页均200，robots允许目标路径。产品页Angular transfer state中包含该型号27条规格，Material Code、EAN、载重速度、XL、厂商EU标签及EPREL链接均按行给出。页面还包含其他型号和汇总展示数据，各自保留独立范围。[规格页](https://www.dunloptyres.com/en/tyres/sport-maxx-rt2)、[robots](https://www.dunloptyres.com/robots.txt)

日本robots地址当前以200返回HTML错误页。美国OE页面200，规格表数据来自页面明确列出的跨域CSV资源。后续核验按各自技术边界推进。

## 解析与身份

- 固定canonical、title及单个ng-state脚本，只解析固定型号响应URL对应的JSON正文，核对型号、slug、语言与季节。
- 只消费所选响应的sizes。其他型号、型号汇总及营销图标维持自身范围，逐SKU字段分别取证。
- 核对Material Code与rep_code、EAN校验位、尺寸几何字段、服务描述与逐字段载重速度的一致性。
- XL仅按明确行级声明记录true，其他情况为null。M+S、雪地、冰地和轮辋保护按行级布尔声明保存。通用mobility字段保留原值，独立防爆与静音事实待进一步依据。
- 产品代码采用MATERIAL_CODE，EAN与厂商EPREL链接独立保留，身份沿既有source_scoped合同。EU标签属于manufacturer_official声明，正式监管绑定继续待验。
- 保存active／phase out原文状态，现有生命周期操作继续依据正式治理流程。

1. 新增确定性HTML／JSON解析器和合成范围、重复编码、字段冲突及畸形输入反例。
2. 接入registry、固定主机归属、Parser目录、可信子进程及17项完整封存包合同，补旧16项包兼容证据。
3. 更新明确来源目录断言及已有回归子进程摘要／精确参数，执行相关受管检查。
4. 执行显式在线canary、正常API和实际非拥有者PG／TLS消费，核对同尺寸两条不同Material Code、原始观察时间、证据重开及资源回收。服务端提供验证器时核对条件读取，当前无验证器时按完整在线读取留证。
