# 正文向量召回与融合重排实施计划

## 目标与合同

将已授权且已建立向量的HTML／PDF正文接入现行hybrid-search。结构化查询先行，查询文本的单次外发确认、预算、幂等与账本共用既有入口。一条查询向量可用于结构化与正文的本地召回，结果中的正文集合保留独立原件引用、词法／向量／融合来源和可复核排序依据。

正文采用既有original-text-semantic@1、接收端和模型空间。每次准备、实际外发前和结果回写阶段读取当前正式HTML头、PDF索引、用途最新修订、原件绑定和内容缓存。候选输出再次从原件恢复，PDF复用受限Parser。同正文的不同引用分别返回，缓存按既有完整接收端合同复用。

HTML页面可参与来源、轮胎来源类型和已登记来源地区的范围检索。PDF采用已保存文档范围，其地区与来源类别依据现有材料元数据表达。精确SKU、品牌、型号、尺寸、技术、车型、测试、召回及字段条件需要相应结构化关联，正文候选按实际可证明范围准入。

新增可选preferred_region作为排序偏好，region筛选仍执行来源／结构化范围约束。无地区偏好的历史请求沿原序列化合同恢复。来源类别由来源目录表达，人工保存的PDF保留未分类状态。正文排序公开来源类别层级、页面范围身份状态、地区匹配、RRF分数和观察时间。PDF保存时间标记为留存时间，发布时间保留未知。

## 实施步骤

1. 复用正文用途、缓存和引用恢复校验，增加当前正文材料与授权缓存映射。HTML投影在受管事务中重建，外发前新会话只读复核。
2. 在同一准入范围执行FTS及真实pgvector余弦，复用RRF，并按来源类别、地区偏好、相关度与观察时间排序。所有SQL条件在候选截断之前应用。
3. 接入现行hybrid-search的准备、最终外发复核、实际用量及幂等恢复，兼容仅结构化、仅正文和混合索引。许可／原件变化时记录实际调用阶段及用量。
4. 增补共享类型、SDK合同及Web正文融合结果卡、排序依据、引用恢复和地区偏好。复用现有正文选择及用途入口。
5. 执行受管API回归、真实PostgreSQL余弦与备份恢复、三端类型、SDK／Web测试及生产浏览器验收，再更新交接。

## 验证重点

覆盖词法与语义同引用融合、语义独有候选、正文独立索引、精确筛选准入、来源及地区截断、过期／撤销／私有策略、原件及投影损坏、配置和端点隔离、外发前与调用期间变化、旧请求序列化及旧历史读取、幂等预算，以及Unicode／PDF引用恢复。

实际模型语义、真实专业材料质量、正文证据包与Responses链路继续按原文RAG总计划验收。本计划的融合结果为后续证据包提供引用。

## 执行结果

正文HTML／PDF向量召回、FTS与RRF融合、地区偏好、来源类别／时间排序、共享类型、SDK和Web已接通。

真实PG首轮发现已存在但损坏的pgvector镜像无法恢复。原失败断言保留，修复采用已校验不可变缓存的批量upsert。第二轮真实PostgreSQL56项通过，153张模型表实际备份恢复指纹一致，损坏镜像恢复后的余弦距离及恢复库引用核对通过。

生产浏览器首轮发现旧词法卡与融合卡重复，修正渲染条件后重新构建并完成29项检查，包含320、390及1440像素视口。六模块API184／184、SDK7／7、Web50／50、三端类型及末次Web生产构建通过。服务与隔离集群已关闭。

本轮采用合成材料及合成Provider，具体回执、历史失败、剩余需求与接手顺序见[当前交接卡](../AGENT-HANDOFF-2026-11-13.md)。
