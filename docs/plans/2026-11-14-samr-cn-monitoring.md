# 中国召回版本、后台监控与通知实施计划

## 目标与依据

沿 `main` 的 `394742a` 接续原规格 P0 Safety 来源。中国召回已有官方检索、原生公告、不可变快照、核验、授权、SDK 和工作台。本计划接通逐公告版本、变化事件、后台调度和通知，完整 V1 继续依据原规格验收。[原始需求](../requirements/2026-09-26-tire-intelligence-original.md)

## 实施顺序

1. 以官方 32 位文章 ID 建立内容版本、快照观察和变化事件，在正常采纳事务及显式历史读取时派生。补齐现有已接受快照，使用有界分页与固定观察序号。原始显示日期、DeployTime、PubDate 和系统观察时间分别保留，顺序依据系统采纳过程。
2. 接通共享类型、SDK 与公告工作台历史入口。展示版本、字段变化、观察时间和原件，继续使用请求取消及来源治理。验证已有快照升级、重复核验、304、内容回退、不同文章身份、失败与篡改反例。
3. 接通明确范围的检索发现与指定公告监控。检索覆盖和逐公告检查分别记录，每轮在线优先并保存所选文章、各页及各公告回执。覆盖范围、原站导航上限、部分失败与未评估的实物适用性在运行结果中表达。
4. 复用既有 Worker 的摄取锁、来源代次、租约、任务阶段和重连 SSE。规则有账户作用域、幂等创建、乐观修订、暂停与归档。每次采纳和最终提交均核对租约、规则修订及来源状态。
5. 从已保存的文章变化事件生成应用内通知，绑定规则修订、前后版本和原件。按规则与事件去重，记录观察、排队、完成时间与实际通知 lag。关键词同时核对变化前后内容，首次观察保留其系统观察语义。
6. 执行受管回归、SQLite 旧库升级、非拥有者 PostgreSQL 权限与正常 HTTP／Worker 验证，以及三端类型、Web 构建和正常浏览器验收。真实来源与合成变化各自保留原始记录，长周期与生产 SLO 依据实际时长验收。
7. 更新交接与阶段验收，检查凭据及个人环境信息，提交并直连推送，核对实时远端 SHA。后续继续 SKU／批次绑定、人工 Golden、许可、AI 引用、真实 Responses／Embeddings 和其他 V1 Gate。

## 版本链不变量

- 每个公告的身份来自来源原生文章 ID，内容版本保存完整规范化公告及摘要，观察绑定一份经过核验的不可变快照。
- 相同快照重复核验与 304 复用已有观察，原文序列化变化可追加观察并复用内容版本。A→B→A 记录三次变化并复用最初内容版本。
- 公告发布日期与页面元数据各自完整保留。后采纳的内容按系统观察顺序追加，历史接口显示已保存观察范围及日期差异。
- 成功采纳与版本派生在同一事务中完成。失败查询、检索列表和单次历史回退沿各自既有路径处理。
- 版本、观察和事件只追加。历史查询核对快照、文章、内容摘要、前后版本和字段差异的绑定。固定 `through_sequence` 的分页在新观察到来后继续读取原先范围。
- 新表通过现有拥有者迁移入口建立，运行角色仅获得必要 SELECT／INSERT。部署前重新建立并批准匹配当前 API 源码的 `@4` 合同。
