# PostgreSQL 应用运行角色计划

2026-11-14阶段交接见[完整交接卡](../AGENT-HANDOFF-2026-11-14.md)。策略、固定锁函数及正式入口已实现，后续[HNSW拥有者维护](../POSTGRES-VECTOR-INDEXES.md)及@4声明解决索引DDL依赖。继续权限专项、Parser性能取证与实际部署验收。

**Goal** — API／Worker 使用经过审查的逐表和逐列 DML 权限运行，数据库拥有者承担迁移与维护。

**Architecture** — 复用许可操作员的有效 ACL 检查。运行策略固定列出当前模型表的读取／追加能力、实际可变列以及删除入口。SQL 生成器输出带前后检查的事务，DBA 显式应用，运行账户通过只读检查核对有效权限。

**Tech Stack** — PostgreSQL catalog、SQLAlchemy、现有 verify schema 合同与隔离 PG 验收。

## 顺序

1. 核对 ORM 历史保护和实际写入点，生成当前 166 表的策略候选，审查所有可变列及删除操作。新模型通过明确更新策略获得权限。
2. 将已有 ACL 检查扩展为可接收固定表／列策略，保留许可操作员的默认行为与测试。新增运行 SQL 生成器和只读角色检查。
3. 新增少量策略回归，验证标识符、可变列、证据保护及旧角色兼容。
4. 在现有 PG 综合验收中增加运行角色模式。迁移、结构实验、扩展安装与备份恢复由拥有者执行，其余 API／Worker 业务流程使用运行账户和 verify 合同。
5. 验证越权 DDL、证据改写、账本删除、额外 ACL、角色成员及权限不足的原子回滚。正常流程缺权时先保留原 SQLSTATE 和入口，再补正必要权限。
6. 运行受管相关回归、角色专项和 PG 综合业务验收，更新部署／交接记录，审查提交并推送。

## 验收边界

角色承担可信应用服务身份，应用继续执行账户与材料授权。生产身份提供方、租户／RLS、远端部署及完整 V1 Gate 继续逐项验收。
